# Office content adapter

Word and PowerPoint expose JSON APIs backed by Graph file downloads and conditional uploads. Org Explorer exposes read-only Graph directory relationships. These services use Microsoft Authentication; they do not request new consent or require Office, Python, or browser data automation on the server.

The XML parser is bundled by `npm run build:content`. ZIP processing uses Node's bounded zlib APIs with CRC checks; no files are extracted to disk. `blank.pptx` is a template generated by `scripts/make-content-fixtures.py` using python-pptx (development only). See `../THIRD_PARTY.md`.

## Word and PowerPoint API

- `GET /capabilities`: supported operations and limits.
- `GET /files/search?q=...&drive=...`: first page of matching `.docx` or `.pptx` files; `drive` defaults to the user's OneDrive. `truncated` signals additional results.
- `POST /documents` or `/presentations`: `{drive,parent,name,content}` creates a simple file. Alternatively provide `{template:{drive,item},operations?}` to copy an existing file and optionally edit the copy. Name collisions fail.
- `GET /documents/{drive}/{item}` or `/presentations/{drive}/{item}`: returns `{file,content}`. `file.version` is an opaque eTag. Content includes element IDs, structure, text, and supported formatting metadata.
- `POST /documents/{drive}/{item}/edits` or `/presentations/{drive}/{item}/edits`: `{version,operations:[...]}` returns the new file version and a change summary. All operations are validated before upload. IDs refer to the read version, so newly inserted elements require another read before targeting them.

Word operations: `replaceText` (paragraph `id`, `find`, `text`, `expectedMatches`, default 1); `setParagraphText` (`id`,`text`); `insertParagraph` (`text`, optional `style`, `before` or `after` paragraph ID; append by default); `deleteParagraph` (`id`); `insertTable` (`rows`, optional body-paragraph `after`); `setCellText` (`id`,`text`). Paragraph styles for insertion are Normal, Title, Subtitle and Heading1–Heading9. Word text inputs and text replacements are single-line; use separate paragraphs for separate lines. Existing line breaks/tabs are respected when matching text and removed when replacing an entire paragraph or cell. A table cell must retain a paragraph.

PowerPoint operations: `replaceText` (paragraph `id`,`find`,`text`,`expectedMatches`); `setShapeText` (text-shape `id`,`text`); `setCellText` (cell `id`,`text`); `setNotes` (slide `id`,`text`); `addSlide` (`title`,`body`,`notes`, optional zero-based `index`); `duplicateSlide` (slide `id`, optional `index`,`notes`); `moveSlide` (slide `id`, zero-based `index`); `deleteSlide` (slide `id`). Slides must retain at least one member. New slides use simple explicit title/body shapes and the presentation's existing layout. Duplicated slides retain their layout, media and independent notes; existing linked charts remain shared and are not edited.

Read/edit-your-files access is restricted to the user's OneDrive. Select **Edit all accessible files** for shared drives and SharePoint. Read connections reject all mutations. Existing Microsoft file permissions still apply.

## Preservation and limits

Untouched package parts are retained byte-for-byte. Edited XML retains unrelated elements and relationships. Text replacement supports matches spanning formatted runs. New replacement text inherits formatting from its first affected run; replacing a whole shape/paragraph/cell uses its first text run. New multiline PowerPoint shape text creates paragraphs. Header/footer, media, charts, comments, and unsupported content remain in the package; they are not flattened or executed. Word reading/editing covers the main document body, not header/footer or footnote text.

Limits: 25 MiB compressed, 100 MiB expanded, fewer than 10,000 ZIP entries, 4 MiB per XML part, 500 edits per batch, 1,000 slides. Encrypted, macro-enabled, digitally signed, malformed, password-protected-for-editing and unsupported XML packages fail explicitly. XML document types and custom entities are rejected. Word editing rejects fields, tracked revisions, content controls and embedded objects in the target. PowerPoint structural edits reject sectioned presentations and custom shows. Slide deletion removes its XML and notes parts, and fails when other package parts link to them. Advanced layout, animations, chart/image creation and tracked-change authoring are outside this version.

Edits require the exact version from a read and use `If-Match` during upload. Stale versions return 412; locked files return 423. There is no automatic merge, lock bypass or unconditional overwrite. If an upload's result is unknown after a transport failure, inspect the file before retrying. Credentials, signed transfer URLs and document data are not logged by the helper.

## Org Explorer API

- `GET /people?q=...`: prefix search over name, email and UPN.
- `GET /people/{person}`: profile; `{person}` accepts `me`, ID or UPN.
- `GET /people/{person}/manager`: immediate manager, or `{person:null}` when none is assigned.
- `GET /people/{person}/manager-chain`: up to 20 managers with truncation/cycle indicators.
- `GET /people/{person}/reports` and `/peers`: direct reports and colleagues with the same manager.
- `GET /people/{person}/subtree?depth=2&maxPeople=500`: bounded breadth-first traversal, max depth 5 and 500 people. `truncated`, `depthLimited` and `cycle` describe traversal boundaries; this does not claim a complete organization total.

List/search endpoints accept `limit` (1–100) and an opaque `cursor` returned as `nextCursor`. Manager chains and subtrees stop at configured bounds. Profiles omit unavailable fields. There are no directory writes or requests for additional consent. Missing manager relationships are normal. Skills, assistants and works-with insights are not part of this version.

## Validation

`npm run check:content -- --silent` reads organization relationships using `.local-profile/microsoft/credentials.json`. Add `--write --pdf` to create, edit, copy, conditionally replace, render through Microsoft Office, and remove disposable files in OneDrive and the selected SharePoint folder. No existing documents are edited. Interrupted cleanup retains item IDs in the owner-only `content-cleanup.json` cache; resolve those items before repeating write checks. Credentials and the dedicated authentication browser profile remain cached.
